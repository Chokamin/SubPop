# 构建14：字幕操作界面

针对用户反馈“插件界面非常不友好”，将原生扩展从诊断控制台改为“导入项目 → 整段识别 → 拖回字幕”。使用 better-ui 技能的层次、状态反馈和克制原则；继续使用 AppKit 原生控件。

## 已实现

- 独立项目拖放卡片，指明从 FCP 浏览器拖入；悬停反馈只接受 FCPXML 类型。收到项目立即校验项目身份，提供项目名和完整视频提示。
- 一个主要按钮：未连接时引导连接，连接后识别；缺少新快照/活动项目或任务运行时禁用。
- 独立状态文案与加载指示，覆盖音频准备、语音识别、字幕整理、重复、冲突、静音、失败、过期及拖出。观察者日志不会持续冲掉任务提示。
- 只有有效新结果才允许拖出；过期、重复和未生成时不可拖。拖出提示不等同于宣称 FCP 写入成功。
- JSON 和三个探针按钮移入可关闭诊断弹窗，主界面没有日志。
- 服务授权默认定位正确目录并明确显示“连接”；容器默认定位工作目录并显示“启动服务”。服务窗口根据自己的 worker PID 与实际心跳显示启动中/就绪/停止。
- 底部保留真实测试范围。未扩大识别支持范围，没有自动写入或覆盖字幕。

## 实际验收

在 FCP 中安装、加载构建14，检查实际截图和辅助功能树。初版实际窗口沿用旧尺寸导致底部说明不可见，已压缩布局并重新安装；最终拖放区、状态、主按钮、范围说明、诊断均可见。

已实际检查：未连接状态；默认目录连接（无路径输入）；绿色已连接状态；无新项目时“开始识别”禁用；诊断弹窗中的JSON和三个按钮可见；弹窗关闭后主界面仍显示“等待导入项目”。容器默认目录启动服务通过，服务心跳正常。

识别中/结果/冲突/静音/过期的文案与控件逻辑已实现并通过编译，但本轮未重新做每一种宿主端到端输入验收；不得将54项原有回归称作这些新UI状态的完整实测。新拖放卡片的用户实际拖入仍待验收。原项目内容未改。

构建、签名及54项现有功能回归通过。构建14已安装，FCP面板打开，服务已启动。支持范围仍是此前隔离8.68秒项目。

## 构建15：根据后续反馈改为单窗口结构

用户追问“为什么没有模型选择，还有2个窗口，需要启动服务是什么意思”。明确说明目前仅接入Qwen3-ASR 0.6B，并将模型名直接放到主界面；“模型与设置”展示实际已安装模型、CPU运行方式及尚不支持切换的限制，没有伪造其他可选模型。

容器改为无常规窗口的后台agent（LSUIElement）；扩展通过固定subpop-probe://start链接启动它。首次目录授权后计划保存各自的security-scoped bookmark；后续面板恢复任务目录并拉起后台。首次后台模型授权以系统文件选择器呈现，不保留第二个服务管理窗口。主界面去掉“连接服务/启动服务”术语。

构建15编译、签名、安装和FCP加载通过，模型名/“准备本机识别”按钮实测可见；54项回归通过，包括后台agent与固定URL scheme注册检查。尚未验证自动启动和授权恢复：点击首次任务目录“允许并继续”被自动审批拒绝，理由为持久访问范围未获用户明确批准。未绕过拒绝，未执行保存授权；已询问用户允许记住授权还是仅本次使用。需回答后继续，不能宣称免授权重开已经通过。
