# 整段音频渲染（构建13）

识别任务现在先还原 XML 定义的时间线音频，再做整段识别。新实现位于 `probes/timeline_audio.py`，原生 AVFoundation CLI 仍只负责经过校验的单段源解码。旧的只读音频诊断不等同于新任务渲染入口。

## 本轮新增能力

- 连续单声道对白片段按各自源起点解码，保留原时间线位置。
- 显式 gap、片段禁用、仅视频、唯一音频组件禁用输出等长静音，不压缩项目时间。
- 支持无关键帧的恒定音量衰减（−96 至 0 dB）。
- 各片段或 gap 上已验证的 Basic Title 单独换算父级时间，重复/冲突检查继续使用原快照。
- 全静音直接返回 `blocked-no-audio`，不加载 ASR、不生成 Title。校验失败有终态及具体原因，后台与面板不会一直等待。

仍固定隔离项目 UID、原测试媒体、8.68 秒、25fps；底层渲染器最多30秒/64段。双声道/多通道、多轨叠加、变速、效果、音量关键帧、J/L cut、未知Title仍明确拒绝。未开放通用项目识别。

## 已完成的验收

FCP 内通过菜单在4秒切割，对前段设−6dB，再关闭前段音频组件，最后用空隙替代前段。分别导出实际XML；基准、有音量调整、前段静音三份WAV仅用于工程对照，导出操作不是产品流程。四项编辑撤销后，独立XML确认整个sequence与之前的基准完全一致（媒体、五条Caption、三条Title、属性与时间）。

`subpop-timeline-mix.json`记录FCP WAV与新渲染器的量化对照：前段相对音量0.501187，后段约1；静音区域仅有极小导出/重采样残差。对齐一个16kHz采样点后，有声部分相关系数大于0.9996。宿主参考还存在约0.707倍固定声道增益差异。因此证明时间、相对音量和静音处理一致，不声称与FCP最终混音逐字节相同；临时角色/Solo监听状态仍不在这个音频计划内。

完整CPU任务：真实双片段音量快照识别三句，并拦截已有三条Title重复。前置空隙快照去除已知静音Title后，用于验证生成路径：输出两句，分别100–140帧、146–214帧，未把后段提前；三个版本Title生成，1.14通过本地Apple DTD。新worker真实文件队列分别回传`ready`和`blocked-no-audio`。详见`subpop-timeline-jobs.json`。这些后台验收与面板新拖入验收分别记录。

## 使用

保持 SubPop 容器应用打开；扩展连接本机服务后，将当前隔离项目拖到顶部说明区，再点击“识别刚拖入的项目”。每次需要新快照，结果不自动写入时间线。已有Title重复/重叠或整段静音时不提供可拖出字幕。
