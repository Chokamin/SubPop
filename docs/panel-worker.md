# 面板启动本机识别任务（构建11）

实现方式：SubPop容器应用通过NSTask启动独立Python worker；FCP扩展通过用户选择的专用目录提交XML快照并轮询状态。无HTTP服务、网络监听或任意命令接口。

## 使用入口

- 打开SubPop Probe容器应用，点击“选择 SubPop 工作目录并启动服务”，选择当前项目根目录。开发探针固定该目录，非发行版路径发现方案。
- 在FCP面板点击“连接本机识别服务”，选择`.subloom/verification/bridge`。每次扩展重开需要重新连接，尚未持久化书签。
- 点击“识别最近项目快照”，面板提交最近一次拖入的XML，显示后台阶段并自动接收Title输出；不再逐次选结果目录。仍需把结果拖入FCP并拆分。

## 限制和校验

输入仍是最近拖入的旧快照，按钮名称和日志明确这一点；本次为08:17:11Z快照，当前原时间线已增加Title。项目UID和时长核对不等于内容新鲜度保证。当前仅支持原隔离8.68秒/25fps普通dialogue片段，最终可听混音未通过。

扩展将XML书签节点移除后提交，避免将FCP的书签凭据交给非沙箱worker。每请求独立UUID、输入SHA、固定UID；request.json原子写入后才处理。worker限制固定工作区、固定Python模块命令、输入大小和路径，校验输入哈希与模型目录。一次仅处理一项；运行时面板禁用启动按钮，并清空旧结果。

worker返回阶段、jobID、快照SHA、PCM SHA和三版本Title字符串/哈希；扩展对请求ID、快照SHA、项目身份/时长与输出哈希验证后才进入ready-to-drag。工作进程心跳失效/任务失败时不能拖出旧结果。worker超时600秒终止识别子进程；重启时将旧running请求标记failed，不静默重复。取消识别按钮、持久任务恢复、按内容去重未完成。

文件权限由原先user-selected.read-only改为user-selected.read-write，仅使用NSOpenPanel选择的任务目录；没有增加网络权限。容器启动最初停在Python初始化的fopen（只读sample证据），没有足够证据断言单一系统权限根因；改为应用内选择SubPop目录后实际成功启动服务，未授予全磁盘访问或改系统隐私设置。
