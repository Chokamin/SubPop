# 新快照与重复 Title 保护（构建12）

## 新快照约束

面板不再从磁盘挑选最近旧XML。只接受当前扩展会话里新收到的项目拖放，并限制提交前5分钟有效；提交成功后即消费该输入，再次识别必须重新拖入。重开面板、切换活动sequence或收到新拖放，会清除旧输入/输出；识别期间收到另一份输入，旧请求结果不能覆盖新输入。

关闭了手动载入旧结果和固定测试fixture拖出入口，以免绕过重复检查。新结果仅在本会话5分钟内可拖出；一次非取消拖放结束后清空输出，避免同一结果连续拖入。FCP拖放结束operation不等于实际成功写入，失败重试仍需重新读取项目。

这只保证每个任务有一次近期的显式项目快照，不提供FCP实时修改订阅。拖入后再编辑项目的变化仍可能不可见；UID和时长相同不保证内容相同。不能宣称已经实现无交互实时项目读取。

## 带已有 Title 的音频输入

新增`probes/snapshot.py`，保留原XML以检测冲突，另建音频副本交给已有严格原生解码器。仅从音频副本移除已实测Basic Title模板，允许文本样式及FCP自动写出的“展平/对齐”两个参数；拒绝其他模板、嵌套音频/片段、filter-audio等未验证特性。原项目和原输入文件不会被改写。此归一化仅针对已验证不产生音频的模板，不是通用Title或最终混音支持。

## 重复与冲突

识别后按实际输出文字、精确25fps起止帧与快照已有Title比较。所有输出都有已启用的相同Title时返回duplicate；存在时间重叠且不能全部精确匹配时返回conflict（包括用户已校对文本、时长变化、部分重复和禁用片段）。两者都返回blocked-existing-titles，不生成Title交换文件、不覆盖现有编辑。未知Title直接拒绝读取，不推断它属于SubPop。

无重叠才生成输出。该行为不是自动更新或合并字幕，也不确认已有Title的作者。样式差异不影响“相同文字+时间”的重复判断；保留原样式。
